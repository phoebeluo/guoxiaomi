# 内部文档区（不对客）

本目录存放**内部运营规范**，与 `data/docs/`（对客知识库）严格分离。
`data/docs/` 下的内容会被注入给顾客对话；本目录下的内容**不会被注入**。

---

## 为什么必须分离

本项目采用 P0 全量注入策略：`data/docs/` 下的每一篇 Markdown 都会被拼进 system 消息。
内部 SOP 一旦混在其中，会同时造成两个问题：

1. **合规风险** —— 内部金额分级阈值、上报链路、内部职务会被模型直接念给顾客
2. **能力自相矛盾** —— 内部文档描述"客服组长 12 小时内介入"这类人工流程，
   而对话模型自身无工单、无代客提交、无回访能力。两者并列会让模型混淆自己的边界，
   进而说出"已为您提交专人跟进"这种它根本做不到的话

---

## 隔离机制

`rag/load_docs.py` 使用**非递归** glob（`os.path.join(folder, "*.md")`），
因此**移入子目录即自动排除，无需在代码里维护黑名单**。

隔离对检索指标无负面影响——这些文档历史上从未进入检索结果前列。

---

## 目录内容与隔离原因

| 文件 | 内容 | 为何属于内部 |
| --- | --- | --- |
| `客服-投诉升级机制.md` | 四级分级表、赔付金额阈值（200/500 元）、上报链路、内部职务 | 金额阈值与组织架构属内部信息；且"专人跟进"话术是模型无法兑现的承诺 |
| `客服-售后处理流程.md` | 内部四步流程、核实时限、结案回访、台账登记 | 全部为"我们内部怎么运转"，非顾客需知 |
| `客服-标准话术.md` | 开场/提问/推荐/安抚的"统一格式"话术模板 | 是给客服人员的执行模板，与 `app.py` 的 Workflow 段功能重复；且模板化表述会与提示词争抢约束 |
| `客服-禁忌用语.md` | 禁用词清单 + 替换话术 | **最危险的一篇**：它把"帮您确认一下，稍后回复您""帮您联系物流核实一下"写成"必须使用的标准话术"，与系统真实能力直接冲突 |

---

## 判据：一段内容该不该对客

问三个问题，任一命中即需处理：

1. **它描述的是"我们内部怎么运转"吗？**（职务、层级、上报链路、时限）
   → 移入本目录
2. **它包含顾客不该知道的数字吗？**（金额分级阈值、内部成本、抽检比例明细）
   → 移入本目录
3. **它要求模型承诺系统做不到的事吗？**
   → **这不是分层问题，是内容错误，必须改写或删除**——移走只是回避，内容本身是错的

第 3 类是本目录最需要警惕的。一份名为"禁忌用语"的文档，本身在教模型说禁忌的话——
根因是写文档的人假设读者是"会遵守规则的人"，而这里的读者是模型，
**它读不出"这是禁令"和"这是模板"的区别**。约束模型时应当只写反例，不写正例。
