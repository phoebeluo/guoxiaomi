# 评测集 · 使用说明

评测集是本项目**最值钱的资产**：它把「系统到底行不行」变成可重复、可比较的数字。
没有它，后续每一次优化（类别路由、BM25、embedding）都只能靠感觉说「好像变好了」。

---

## 文件

| 文件 | 作用 | 谁维护 |
| --- | --- | --- |
| `cases.jsonl` | **题目与判定标准**（一行一题） | **你**（标注不可代劳） |
| `reports/` | 历次运行结果 | 脚本自动写入 |
| `../tools/eval_run.py` | 运行器：读题 → 调模型 → 判定 → 出报告 | 已就绪 |

## 题目字段（每行一个 JSON）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✓ | 整数，**必须唯一**（改了题目就换号，别复用） |
| `q` | ✓ | 提问原文。**必须是具体事实问句**（见下方「坑」） |
| `expect` | ✓ | `has` / `none` / `constraint`，三选一 |
| `pattern` | ✓ | 正则。三种类型都靠它判定 |
| `source` | ✓ | 依据文件；反向题写「语料中无此信息」。**给人看的**描述 |
| `gold_sources` | ✓ | **金标篇目列表**（2026-10-15 新增）。**给机器用**：`has` 题 ≥1 篇、`none`/`constraint` 题为 `[]`；元素只写 `data/docs/` 下的文件名。见下方「金标」节 |
| `category` | ✓ | 所属一级类别（百科/售后/客服/配送/交易/服务/品控/会员/优惠/—） |
| `kind` | ✓ | **失败时该修什么**（`fact`/`gap`/`boundary`/`rule`），见下节 |
| `counted` | | 默认 `true`。写 `false` = **不计入通过率**（对照组题），见下节 |
| `holdout` | | **留出集标记**（2026-10-19 新增）。`true` = 8 题封存题，只用于 W13 最终汇报；W3–W8 调参须加 `--no-holdout` 排除。见 `../docs/过程记录/留出集清单-20261019.md` |
| `note` | | 给自己看的备注 |

## 三种判定类型

| `expect` | 含义 | `pattern` 期望 | 典型场景 |
| --- | --- | --- | --- |
| `has` | 语料**有**答案，必须命中 | **必须匹配到** | 事实问答 |
| `none` | 语料**没有**该信息，不得编造 | **不得匹配到** | 「你们发什么快递」 |
| `constraint` | 约束红线，不得触碰 | **不得匹配到** | 「能保证绝对新鲜吗」 |

> `none` 与 `constraint` 都是「不得匹配」，分开写是为了**统计时能分栏**——
> 前者测「会不会编造」，后者测「长上下文塞进去后约束有没有被稀释」，是两个不同的失效模式。

## 金标（`gold_sources`）· 2026-10-15 新增

**完整口径见 `../docs/金标规则说明-20261015.md`**，此处只记要点。

| 项 | 约定 |
| --- | --- |
| 定义 | 「有金标」= 存在至少一篇 `data/docs/*.md`，其正文能**独立支撑**该题 `pattern` 所需事实 |
| 与 `source` 的分工 | `source` 给人看（可自由描述）；`gold_sources` 给机器用（列表、纯文件名） |
| 与 `expect` 的对应 | `has` → ≥1 篇；`none` / `constraint` → `[]` |
| 分类 | 可回答(1 篇) / 多答案(≥2 篇) / 库外(0 篇)，目标比例 **7:2:1** |
| 谁在用 | oracle 策略 `inject-gold`（按金标注入）、覆盖率统计、`--check` 校验 |

**两个易踩的坑**：

1. **别把「相关但不支撑」的篇目塞进来**——会让 oracle 从「理想检索」变成「超额注入」，A/B 对照失效。
2. **`售后-常见问题汇总.md` 是「答案富集篇」**，复述了时效/快递/运费/自提/溯源等多处答案，多答案题大多含它。

> 校验已内置：`tools/eval_run.py --check` 会检查 `gold_sources` 存在、是列表、元素真实存在，且与 `expect` 自洽。

## `kind`：失败时该修什么（2026-10-12 新增）

`expect` 回答的是「**怎么判定**」；`kind` 回答的是「**失败了该去修哪里**」。
这是两个不同的问题——`#4`（快递）就是把它俩混为一谈、修错方向的案例。

| `kind` | 含义 | 一眼判断法 | 失败时该修 | 现有题 |
| --- | --- | --- | --- | --- |
| `fact` | A·事实覆盖 | 语料里**找得到**答案 | 改提示词 | #1 #2 #3 #4 #6 #7 #10 #11 #12 #13 #14 #16 #18 #19 #20 #21 #22 |
| `gap` | B·知识盲区 | 语料里**没有**，但这答案是客观事实 | **补语料** | **暂无**（`#4` 已于 2026-10-12 补语料后升级为 `fact`） |
| `boundary` | C·能力边界 | 答案**客观上拿不到**（要实时接口） | 保持拒答 + 指路 | #9 |
| `rule` | D·约束红线 | 测的是「行为规范」 | 改提示词 | #5 #8 #15 #17 |

### 为什么要拆 `gap` 和 `boundary`（本节的要点）

它们现在都被塞在 `expect: none` 里。**注意：两者的当前正确行为并不冲突**——
都是「不得编造、如实说明我这边没有」；区别在**长期处置**：

| 题 | 语料有吗 | 答案客观可得吗 | 当前正确行为 | 长期处置 |
| --- | --- | --- | --- | --- |
| `#4` 发什么快递 | ✅ **已补** | ✅ 快递公司是稳定的客观事实 | 应直接答出承运方 | **2026-10-12 已补语料** → 升级为 `fact`（见《配送-物流承运商》） |
| `#9` 物流到哪了 | ❌ | ❌ 必须走实时接口才拿得到 | 不编造 + 拒答 + 指路 | **保持拒答** → 静态语料永远补不上这一栏 |

→ 所以区分标准不是「答案相不相反」，而是 **「这个洞能不能靠补语料填上」**：
- 能填 → `gap`（去改 `data/docs/*.md`）
- 填不上 → `boundary`（去改提示词里的指路话术）

→ 若不分，`#4` 失败时你会以为"模型编造了"（去改提示词），
实际是**你的语料漏了一栏**（该去补语料）。**修错方向，问题永远不会消失。**

### 常规搭配（`tools/check_kinds.py` 自动校验）

| `expect` | 通常配的 `kind` |
| --- | --- |
| `has` | `fact` |
| `none` | `gap` 或 `boundary` |
| `constraint` | `rule` |

不在此表的组合会**提示但不报错**——组合本身可能是你有意的设计。
但**已知的、确认过的例外**会归到「已备案例外」单独输出，不再反复打扰你。

**已备案例外**：`#15` 是 `expect: none` + `kind: rule`。
它测「不得承诺代办」这条**行为红线**，本该记 `constraint`；但判据逻辑上
`none` 与 `constraint` 完全相同（都是 `ok = not hits`），只是统计分栏不同。
**已确认维持现状**，理由写在 `tools/check_kinds.py` 的 `KNOWN_EXCEPTIONS` 里。

## `counted`：这道题算不算进通过率（2026-10-12 新增）

有些题的答案属于**模型自带的常识**（如 `#7`「榴莲热量多少」），
**一句语料都不给它也能答对**。这类题混进分母会制造一个假象：

> 通过率很高，但高出来的那部分**跟「知识库接上了没有」毫无关系**——
> 等于拿模型本来就有的本事，给你的优化记功。

| `counted` | 含义 |
| --- | --- |
| `true`（默认，可不写） | 计入通过率，它的分数能反映知识库贡献 |
| `false` | **不计入**任何通过率，报告里单独列为「对照组题」 |

**当前对照组**：`#7`（榴莲热量）。

它们不是废题，而是**校准项**——告诉你 A/B 两策略的差值里，
有多少本来就是模型自己会的东西。

## 写法三条要点

**1. `pattern` 要用正则容忍同义表述。**
反面教材：写「10 至 11 月」，模型答「10 到 11 月」→ 误判为未命中。
正确写法：`10\s*[到至\-—~～]\s*11\s*月`。**关键词死匹配是 RAG 评测最常见的坑。**

> ⚠️ **区间连接符必须同时收全角与半角。** 2026-09-30 实测踩坑：
> 判据写 `[到至\-—~]`，模型输出的是「6**～**12 元/斤」（全角 `～` U+FF5E），
> 半角 `~`（U+007E）匹配不到 → 一道本该通过的价格题被判失败。
> 完整的连接符集合：`[到至\-—–~～]`（含 减号/短破折/长破折/半角波浪/全角波浪）。
> **这类错字符级误判不会报错，只会静默地把正确回答判成失败。**

**2. 事实类必须问具体，泛问要单独归类。**
问「柚子推荐」会触发 system_prompt 的**反问分支**（「您想自己吃还是送人呀」），
既不引语料也不是拒答。这是设计行为、不是缺陷。
所以泛问若入集，`expect` 应另设一类，**否则会把反问误判成「注入失效」**。

**3. 每题都要能回答「依据在哪」。**
`source` 必须指向真实文件。答不上依据的题不要入集——
因为**你无法判断模型是答对了还是蒙对了**。

**4. `pattern` 只写「能证明答对了」的硬证据，别写模糊话题词。**
反面教材：`当天.{0,4}送到`。模型无语料时回
「确实没有『几点前下单可当天送到』的截单时间**记录**」——
这半句是**复述你的问题**，却被正则匹到，判成了「命中」。
正确写法：只认 `15\s*[:：]\s*00` 这类**具体数值**。
**能证明「答对了」的只有具体事实，不是话题词。**

## ★ 判据的语义盲区（最容易犯错的地方）

**`pattern` 命中 ≠ 模型使用了这个说法。** 同一个词有三种角色：

| 角色 | 例子 | 算命中吗 |
| --- | --- | --- |
| **使用** | 「我们的水果绝对新鲜」 | ✓ 算（违反约束） |
| **否认** | 「果小蜜**不敢**跟您说『绝对新鲜』」 | ✗ **不算**（它守住了约束！） |
| **复述** | 「没有『当天送到』的记录」 | ✗ 不算（它没答出答案） |

不区分这三者，判据会**同时**犯两种错，而且方向相反：

- **假阴性** —— 模型用「不敢说 X」的方式拒绝，却有 X 这几个字 → 被判违规
- **假阳性** —— 模型复述你的问题 → 被判命中

`eval_run.py` 的 `judge()` 里有一层 `NEGATION` 正则，对**紧邻前置**的
`不敢/不能说/不会说/不承诺/杜绝` 等词做过滤，用来解决「否认」这一角色。

> **改判据后必跑回归测试**（`tools/test_judge.py`，零成本，**19 例**真实样本；15 例 → 19 例为 2026-10-19 修 4 个判据 bug 时新增）。
> 判据本身也会犯错，而且**误判方向不总是偏乐观**——它会把系统判成通过，也会**把答对判成答错**。
> 这个坑本项目已踩过多次，2026-10-13 又新增两类：
>
> | 类别 | 实例 | 后果 |
> | --- | --- | --- |
> | **数字与连接符之间插入单位** | 判据 `50\s*[到至]\s*90` 匹配不上模型写的『50 元 至 90 元』 | 模型答对被判失败（`#10` / `#16`） |
> | **同一判据被多题共用** | `#6` 与 `#16` 同一条判据：`#6` 侥幸通过、`#16` 被撞破 | 同一标准产出不一致结果 |
> | **坏样本冒充失败** | `inject#19` 存档回答只有 10 个字符（被截断的响应） | **不抛异常**，却被判成「模型答错」 |
>
> 前两类已改为 `[^0-9]{0,8}` 容忍段 + 加 4 例回归；第三类已在 `write_report` 加
> **「可疑样本」告警**（回答 < 12 字符，只告警、不改判定）。
> ⚠️ 教训：**A/B 跑出落差时，先怀疑测量，再怀疑模型。**

## 坑（必读）

- **改了语料 = 本次评测作废。** 语料一冻结，评测集才有对照组意义。
  （2026-10-12 两次补语料均触发作废：补《配送-物流承运商》→ 基线 94%（17/18）；
  再补《配送-门店自提》《品控-溯源与质检》并扩题至 22 题 → 须再重跑建立新基线。）
- **改了 `system_prompt` 也要重跑。** 运行器直接从 `app.py` 提取提示词，
  A/B 两个策略都会跟着变 —— 旧报告的数字不再可比。
- **自动判定必须配人工复核。** 脚本只能给出初筛；判定标红时先怀疑**判定逻辑**，
  再怀疑模型答错（这个坑本项目已经踩过两次：一次误报刷分、一次误杀合规回答）。
