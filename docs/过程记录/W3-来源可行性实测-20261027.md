# W3 来源可行性实测 · 2026-10-27

> 对应主轨 **W3 第 1 步（语料来源清单）**。
> 方法：`tools/probe_source.py`（新增）对 12 个候选源逐个发 1 次 GET，看**静态 HTML 里有没有中文正文**。
> 判定：HTTP 200 + 正文 ≥300 中文字 + 中文占比 ≥35% → OK。
> ⚠️ 本步只测「能不能拿到正文」，**不测频率限制**——批量抓时还要再验一次。

## 二、结论：计划里的四类来源，实际只有一类能抓

主轨 W3 第 1 步写的是四类来源：① 生鲜电商 SKU 商品页 ② 国标/地理标志 ③ 成分表与食用禁忌 ④ 公开客服政策族。

实测把这张纸打了个对折：

| 计划里的来源 | 实测 | 处置 |
|---|---|---|
| ① 生鲜电商 SKU 商品页 | **全军覆没**（403 / 要登录 / JS） | **放弃**，别在这上面耗 |
| ② 国标 / 地理标志 | ✅ 国标平台 + 农产品质量安全网可抓 | **保留，作辅源** |
| ③ 成分表与食用禁忌 | ✅ 食品伙伴网可抓，且量最大 | **升为主源** |
| ④ 公开客服政策族 | ❌ 京东等全部 JS 渲染 | **放弃电商政策，改用「行业通识」类文章**（食品伙伴网的科普/政策解读） |

### 新来源方案（2 主 + 2 辅）

| 角色 | 来源 | 目标篇数 | 抓什么 |
|---|---|---|---|
| 主源 A | 食品伙伴网 | ~180 | 水果成分、保鲜、禁忌、农残、标签标识解读 |
| 主源 B | 中国农业信息网 | ~150 | 品种特性、产地、栽培、采后贮运 |
| 辅源 C | 农产品质量安全网 | ~50 | 地理标志、等级规格、质检口径 |
| 辅源 D | 国标平台 | ~20 | 等级规格条款（注意 PDF 要另处理） |

合计 400 篇，实际可先做 150 篇档。

## 三、这个结果对 W3 的两个影响

**① 好消息：切分返工风险大幅下降。**
原计划最担心「商品页字段化 → 句长骤降 → 必须先改 `split_sentences`」。
现在主源是行业资讯与政策解读，都是**段落型中文**，句长分布大概率接近现有 45 篇（中位 25 / P90 50）。
所以第 2 步的小样验证仍然必做，但「先改切分再爬」的概率降低了。

**② 坏消息：语料域会偏「行业通识」，与果小蜜自有政策语料有冲突风险。**
外部来源里会出现别家的运费门槛、赔付标准、会员规则。一旦混进 `data/docs/`，
`配送 / 售后 / 会员 / 优惠` 这四类题的 `gold_sources` 就会指向互相矛盾的篇目，
W4 的衰减曲线测到的「准确率下降」就变成了「我自己把语料写矛盾了」。

**硬规则（写进抓取脚本，不靠记性）**：
1. 果小蜜自有 45 篇是政策类**唯一真源**；外部语料只进 `百科 / 品类 / 成分 / 标准` 域。
2. 外部文件名统一前缀 `行业-`，与自有语料在文件名上就能分开。
3. 抓取后跑一次冲突扫描：外部语料里出现 `满 99 / 会员等级 / 赔付比例 / 免运费` 等自有专有事实的，**整篇剔除**。
