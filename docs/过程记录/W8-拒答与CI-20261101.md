## 一、拒答：分数判别被实测证伪

### 原始设计

计划写的是「必须用有界分数（余弦），BM25 无界分数做阈值实测无效」。
潜台词是：换成有界分数就能设阈值了。

**这个潜台词是错的。有界只保证「能定义阈值」，不保证「存在能分开两类题的阈值」。**

### 实测数据（45 篇档，54 库内 / 6 库外，扣留出集）

| 组 | 最小 | P10 | 中位 | 最大 |
|---|---|---|---|---|
| 库内（该回答） | 0.479 | 0.758 | 0.899 | 0.992 |
| 库外（该拒答） | 0.654 | — | — | 0.898 |

**区间完全交叠。** 阈值扫描：

| 阈值 | 误拒率 | 漏拒率 |
|---|---|---|
| 0.70 | 6.2% | 75.0% |
| 0.75 | 8.3% | 50.0% |
| 0.80 | 18.8% | 50.0% |
| 0.90 | 52.1% | 0.0% |

要让漏拒归零，得误拒 **52%** 的能答问题；要让误拒归零，漏拒 100%。**不存在可用阈值。**

**根因**：库外题不是「无关话题」，而是「相关话题、库里没写」。
「投诉怎么分级」与语料共享大量词汇，余弦自然高。
**相似度衡量的是字面接近，不是「库里有没有答案」。**

产出：`tools/calibrate_refusal.py` → `eval/reports/refusal_threshold.md`

## 二、替代方案：规则化能力边界清单

`rag/refusal.py`，5 条规则 + 1 条内部信息规则，命中即给**指路话术**，不调模型。

| 规则 | 拦什么 |
|---|---|
| 查订单物流 | 物流到哪 / 没更新 / 帮我查 |
| 代改订单 | 帮我改地址 / 取消 / 催 |
| 登记回访 | 帮我登记 / 让专人联系我 |
| 赔付审批 | 帮我申请赔付 |
| 内部流程细节 | 内部怎么分级 / 谁负责 |

**设计原则：宁可漏拒，不可误拒。** 两者代价不对称——误拒是「能答的问题被推开」，
漏拒还能靠 prompt 的「不知道就明说」兜底（实测 0 条模型失败）。所以规则写得很窄，
只收「动作明确 + 对象明确」的组合。

### 验收

| 指标 | 结果 |
|---|---|
| 误拒（库内题被拦） | **0 / 54** |
| 拦截（库外题） | **3 / 6**（#8 #9 #15） |
| 漏掉 | 3 / 6（#5 #17 #59，绝对化承诺类，按设计交给 prompt） |

第一版规则把「退款多久到账」也收进「赔付审批」，误拒了 `#33`。
`#33` 的答案写在《售后-退款到账时间》里，是**知识问题不是能力问题**，已删掉该分支。

### 线上接入

`app.py` 在调模型**之前**拦：命中就给话术 + `st.stop()`，`requests.jsonl` 记 `refused: 规则名`。
理由：这类问题的正确答案是固定指路话术，调模型既浪费 token，又给它编造的机会。

### 一个测试写错的教训

`test_b_affects_ranking` 最初断言「b=0 与 b=1 的 top3 必须不同」——**失败了**，
因为实测 b 从 0 调到 1，48 题里 46 题排序不变（这正是 `b_sweep` 的结论）。

断言改成「同一个文档的**分数**必须变」——只验证 b 参与了计算，不假设它会改变排序。

> **测试不能假设结论。** 把「b 不敏感」这个发现写成断言，测试就会变成假失败。
