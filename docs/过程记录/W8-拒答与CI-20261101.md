## 一、拒答：分数判别被实测证伪

### 原始设计

计划写的是「必须用有界分数（余弦），BM25 无界分数做阈值实测无效」。
潜台词是：换成有界分数就能设阈值了。

**这个潜台词是错的。有界只保证「能定义阈值」，不保证「存在能分开两类题的阈值」。**

### 实测数据（45 篇档，54 库内 / 6 库外，扣留出集）

| 组 | 最小 | P10 | 中位 | 最大 |
|---|---|---|---|---|
| 库内（该回答） | 0.479 | 0.758 | 0.899 | 0.992 |
| 库外（该拒答） | 0.654 | — | — | 0.898 |

**区间完全交叠。** 阈值扫描：

| 阈值 | 误拒率 | 漏拒率 |
|---|---|---|
| 0.70 | 6.2% | 75.0% |
| 0.75 | 8.3% | 50.0% |
| 0.80 | 18.8% | 50.0% |
| 0.90 | 52.1% | 0.0% |

要让漏拒归零，得误拒 **52%** 的能答问题；要让误拒归零，漏拒 100%。**不存在可用阈值。**

**根因**：库外题不是「无关话题」，而是「相关话题、库里没写」。
「投诉怎么分级」与语料共享大量词汇，余弦自然高。
**相似度衡量的是字面接近，不是「库里有没有答案」。**

产出：`tools/calibrate_refusal.py` → `eval/reports/refusal_threshold.md`

## 二、替代方案：规则化能力边界清单

`rag/refusal.py`，5 条规则 + 1 条内部信息规则，命中即给**指路话术**，不调模型。

| 规则 | 拦什么 |
|---|---|
| 查订单物流 | 物流到哪 / 没更新 / 帮我查 |
| 代改订单 | 帮我改地址 / 取消 / 催 |
| 登记回访 | 帮我登记 / 让专人联系我 |
| 赔付审批 | 帮我申请赔付 |
| 内部流程细节 | 内部怎么分级 / 谁负责 |

**设计原则：宁可漏拒，不可误拒。** 两者代价不对称——误拒是「能答的问题被推开」，
漏拒还能靠 prompt 的「不知道就明说」兜底（实测 0 条模型失败）。所以规则写得很窄，
只收「动作明确 + 对象明确」的组合。

### 验收

| 指标 | 结果 |
|---|---|
| 误拒（库内题被拦） | **0 / 54** |
| 拦截（库外题） | **3 / 6**（#8 #9 #15） |
| 漏掉 | 3 / 6（#5 #17 #59，绝对化承诺类，按设计交给 prompt） |

第一版规则把「退款多久到账」也收进「赔付审批」，误拒了 `#33`。
`#33` 的答案写在《售后-退款到账时间》里，是**知识问题不是能力问题**，已删掉该分支。

### 线上接入

`app.py` 在调模型**之前**拦：命中就给话术 + `st.stop()`，`requests.jsonl` 记 `refused: 规则名`。
理由：这类问题的正确答案是固定指路话术，调模型既浪费 token，又给它编造的机会。

### 一个测试写错的教训

`test_b_affects_ranking` 最初断言「b=0 与 b=1 的 top3 必须不同」——**失败了**，
因为实测 b 从 0 调到 1，48 题里 46 题排序不变（这正是 `b_sweep` 的结论）。

断言改成「同一个文档的**分数**必须变」——只验证 b 参与了计算，不假设它会改变排序。

> **测试不能假设结论。** 把「b 不敏感」这个发现写成断言，测试就会变成假失败。

## 五、修 J1 / J2（2026-11-02 补做，零 API）

### J1 · `HARD_REFUSAL` 的「查不到」有歧义

实证（C 策略 #45「积分会过期吗」）：答案正文正确写出「次年 12 月 31 日 / 年底清零」，
只在结尾说「果小蜜这边**查不到实时数据**，您可以登录账号查看」。旧判据做**子串直判**，
一见「查不到」就记拒答 → `ok = bool(hits) and not refusals` 直接翻成失败。

**判据把模型的优点（诚实说明能力边界）算成了缺点。**

修法：只对歧义词「查不到」看**其后文作用域**（`_DATA_SCOPE`：实时/数据/余额/明细/订单/物流/进度/账户/账号/积分/记录）。
命中作用域词 → 是能力边界，不计拒答；否则仍算拒答。其余短语（暂时没有资料 / 没有这项信息 / 确实没有记录）语义单一，仍直判。

反向用例同时锁死：**真的说「查不到相关资料」仍须判为拒答**，防止放宽过头。

### J2 · `NEGATION` 缺「能力否定」词

实证（C 策略 #15「帮我登记让专人联系我」）：模型答「我的系统能力确实**不包含**“代客提交申请”或“**转接人工**回访”的功能」。
「不包含」不在否定词表里（原表只有 不敢/不能/没法/无法/没有/不存在/不会/不跟您说/不承诺/不许说/不夸）
→ 命中「转接人工」未被剔除 → 守住边界被判成承诺代办。

修法：词表补 `不包含|不提供|不具备` 三个**能力否定**短语。**不加裸「不」**——裸「不」会把「不贵」「不少」这类正向词当否定，误杀不可控。
