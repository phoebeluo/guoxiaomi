## 一、先说清楚放弃了什么

原计划的试用是**唯一能反驳「语料和评测都是你自己造的」的证据**。不做了，这条就空着。

| 影响 | 具体 |
|---|---|
| 简历 | **不能**写「真实用户」「用户反馈驱动迭代」 |
| 面试被问「多少人在用」 | 只能答「目前是我自己在测」 |
| README | 不能出现任何暗示有真实用户的表述 |

**这条限制已经写进 README 的已知边界，改口就是造假。**

## 二、替代方案能测什么、不能测什么

| | 内容 |
|---|---|
| **能测** | 同一套系统，换成我没设计过的 40 种说法（极简 / 方言口语 / 情绪投诉 / 多问题混问 / 砍价 / 健康 / 越界），可信度指标掉多少 |
| **不能测** | 真实用户的分布、真实需求里我没想到的那一类问题 |

一句话：**这是「换问法」，不是「换人」。** 两者价值不同，别混着说。

## 三、为什么只判三件事，不判「答得对不对」

「答得对不对」需要金标。金标由我写 → 又是自己判自己，偏差闭环。

所以只判三件**可机判、且与金标无关**的事：

| 指标 | 定义 | 为什么不依赖金标 |
|---|---|---|
| 出处覆盖率 | 回答里有没有 `【来源：…】` | 只看有没有，不看内容 |
| **出处越界率** | 标注的篇名是否都在本轮注入范围内 | 注入范围是运行时可验证的事实 |
| 禁用话术率 | 代客承诺 / 假装操作 / 绝对化 | 词表是项目既定红线，与题目无关 |

> **可信度可以脱离金标判，正确性不行。** 这是本轮最重要的一句方法论。

## 四、最终结果

| 指标 | 结果 | 分母 |
|---|---|---|
| 出处覆盖率 | **93%** | 28（有注入的题） |
| **出处越界率** | **0%** | 40 |
| 禁用话术率 | **2%** | 40 |
| 零命中自造出处 | **0/12** | 12 |

消耗：输入 136,720 / 输出 6,138 token（qwen3.8-max-0902）。

> 零命中的题**不该有出处**（手上没资料），所以出处覆盖率只在有注入的题上算。
> 用一把尺子量两件事，会得出「加了兜底反而变差」的荒谬结论。

对比意义：**60 道题库上禁用话术率是 0%，换 40 种问法后是 2%（1 条）。**
这个 2% 很小，但它证明了一件事——**题库确实有乐观偏差，只是没有崩**。

## 五、四个真 bug（这比 2% 那个数字值钱得多）

这一轮真正的产出不是指标，是下面四条。每条都是「不换问法就永远发现不了」的。

### bug 1：零命中时模型直接编具体金额

「便宜点呗」→ 检索 0 篇 → 模型输出：

> 「阶梯满减自动享：满 **199 减 20**、满 **299 减 35**、满 **499 减 60**」

知识库根本没用上，这些数字是它从训练记忆里掏出来的。

**第一版修法**：零命中块里写「请按能力边界如实告知没有这项信息」——**模型不听**。

### bug 2：改成禁止性指令后，数字没了，但自造出处

零命中块改成「严禁给出任何具体数字 / 严禁标注来源」后：

> 「咱们店里有阶梯满减活动……【来源：**交易-促销活动规则**】」

这个文件**不存在**（真实文件叫 `优惠-限时活动与满减.md`）。
模型为了让回答「看起来有依据」，凭空造了一个听起来合理的文件名。

**最终修法**：零命中在**代码层**兜底，不调模型 —— `core.zero_hit_reply()`。
分两类：寒暄/无锚点 → 反问；具体但库里没有 → 明说没有 + 指路。

理由：检索 0 篇 = 我手上没有任何资料，这时候让模型开口就是纯风险敞口，还白花一次调用。

### bug 3：模型把提示词的小节标题当成篇名

> 「在线客服每天 9:00 至 21:00【来源：**Capability Boundary**】」
> 「绝不会瞎编乱造【来源：**Constraints**】」

它把 `rag/prompt.py` 里的 Markdown 标题当成了参考文档。

**修法**：知识块第一行显式写出「本轮可用来源：A、B、C」。
只讲「出处只能来自本轮篇名」不够，它得先知道**本轮到底有哪几篇**。

### bug 4：判据把否定句判成违规（又是这一类）

> 「果小蜜**没办法承诺**"绝对最新鲜"或"100%无损"」

被判成绝对化用语。根因：否定词表里有「没法」，**没有「没办法」**（中间隔一个「办」字）。

这是本项目第 **9** 次栽在「提及 ≠ 断言」上。修法与前面一致：补词表 + 加回归用例。

## 六、判据口径错，比模型答错更危险（本轮第二个教训）

首轮 40 条里 8 条「失败」，只有 3 条是真问题。剩下 5 条全是判据错：

| 被判成 | 实际 | 为什么错 |
|---|---|---|
| 代客承诺「帮您查一下」×5 | 订单状态、配送时效**真有工具** | 把「能兑现的承诺」当成空承诺 |

把「帮您查一下订单状态」判成违规，等于要求模型**假装自己没这个能力**——
这和「不许空承诺」是相反方向的错误。

修法：全局红线只留**任何情况下都不许说**的（已为您催 / 已为您改 / 稍后回复您），
「帮您查一下」这类挪到按题配置（`forbid` 字段）。

## 七、测不出来的东西（已知限制）

| 限制 | 说明 |
|---|---|
| **判不出「篇名对、内容错」** | #4 把「满 199 减 20」标成《配送-运费与包邮门槛》（该文档无满减档位）。篇名在注入范围内，本测试判不出来 —— 这需要 entailment 判定（判断某句话是否真出自某篇），成本远高于当前规模 |
| 判不出「答得对不对」 | 没有金标，只能判可信度 |
| 40 条是我构造的 | 比 60 题多样化，但仍不是真人分布。**这层偏差消不掉** |
| 单模型单次 | qwen3.8-max-0902 一次运行，未做重复采样 |

## 八、和 W11 的关系

W11 的对抗测试针对**工具层**（假前提、篡改结论、参数注入）；
本轮针对**知识问答层**（短问、寒暄、情绪、越界、绝对化）。

两轮合起来覆盖了客服系统的两个失败面：
**「该给事实的时候给不给得对」**（W11）和**「没有事实的时候会不会编」**（W13）。
