## 一、先定义"高级"：6 条硬门槛

"高级"不是"功能多"，是"可被追问而不崩"。达到以下 6 条即为面试级：

| 编号 | 维度 | 门槛 | 面试官会问什么 |
|---|---|---|---|
| D1 | 检索可控 | Recall@3 ≥ 0.85 | "凭什么说检索准？数据集多大？" |
| D2 | 幻觉可控 | 幻觉率 ≤ 8% | "怎么量化幻觉？和拒答怎么权衡？" |
| D3 | 拒答可控 | 误拒 ≤ 10%、拒答准确 ≥ 85% | "拒答率和准确率为什么不能只看一个？" |
| D4 | 多轮可控 | 多轮子集准确率 ≥ 80% | "指代词怎么消解？失效了怎么办？" |
| D5 | 工程可控 | 测试/CI 绿灯，P95 ≤ 2.5s | "改一行 prompt 怎么保证不回退？" |
| D6 | 成本可解释 | 有帕累托前沿图 + 单次成本 | "效果和成本怎么取舍？" |

**关键认知**：RAG 本身是及格线，不是加分项。**加分项是"取舍证据"**——为什么选 RRF 不选分数加权、为什么这个 chunk 参数最优、成本与效果换到哪一点停下。

## 四、逐阶段明细：产出与验收

### P0 Python 最小集（10–15 h）
- **只学 5 个主题**：文件读写、目录遍历、字符串 split/join/切片、列表操作、函数定义
- **明确不学**：装饰器、async、类继承、numpy、pandas
- **验收**：能独立写出 `count_docs.py`（已完成）

### P2 切分（8–12 h）
- **产出**：`rag/chunk.py`，44 篇 → 60–90 块
- **必须理解**：`chunk_size` 与 `overlap` 各自的作用；overlap 为何必须按整句回退
- **验收**：块数落在 60–90、每块带 `source`、抽检首尾是完整句子

### P3 BM25（15–20 h）—— 全项目技术壁垒
- **产出**：`rag/bm25.py` + 检索入口
- **必须理解**：IDF 公式为何要 `+1`；`k1` 控制词频饱和；`b` 控制长度归一化
- **必须踩的坑**：jieba 把「车厘子」切成「车厘/子」→ 必须加领域词典
- **验收**：5 题自测中 4 题以上，top1 命中正确文档

### P4 评测集（8–10 h）
- **产出**：`eval/questions.jsonl`，20–40 题
- **必须你亲自做**：`gold_sources` 是列表不是单值；三类题比例约 7:2:1（可回答 / 多答案 / 库外）
- **这一步不可代劳**：标注是业务判断，别人标了你也不懂

### P6 基线数据（4–6 h）
- **产出**：第一组 `Recall@k` / `MRR` 数字
- **验收**：数字可复现，且你能解释每一个指标的含义

### P7–P10（标准版核心）
- RRF 融合：能解释为何 BM25 分数无界、余弦有界，量纲不可比
- 指代消解：3s 硬超时 + 静默降级
- 拒答判别器：**注意 BM25 无界分数做全局阈值是无效的**（实测过：F1 与"全判可回答"完全相同），必须换有界分数
- 工程化：pytest + CI，Prompt 变更自动回归比对

## 八、加速与减速因素

**能加速的（AI 可用，但要守边界）**：

| 内容 | 占比 | 原则 |
|---|---|---|
| 脚手架、依赖安装、跑分脚本、README 初稿 | ~50% | AI 全权代劳，你只验收 |
| 算法公式讲解、指标定义、报错诊断 | ~30% | AI 生成，**你必须能复述原理** |
| 语料判断、评测标注、实验结论、面试叙事 | ~20% | **必须你亲自做，不可代劳** |

**会减速的（提前规避）**：
- 语料返工 —— 索引与评测全部作废。**已冻结，不要中途改内容**
- 卡在环境/配置 —— 你已跨过此关，剩余风险低
- 追求参数最优 —— P2/P3 阶段先跑通，参数寻优留到 P11
- 用 AI 代写全部代码 —— 会导致面试讲不清而被迫删除项目（已有过此次教训）

**红线**：**任何写进简历的数字和设计，必须能讲满 3 分钟。讲不出来的，删掉。**
