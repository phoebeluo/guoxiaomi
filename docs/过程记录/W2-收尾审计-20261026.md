## 二、发现：评测器本身跑不起来（W2 最值钱的一条）

### 症状

```
$ python tools/eval_run.py --check
  File "tools/eval_run.py", line 291
    NEGATION = re.compile(r"(不敢|不能|没法|无法|没有|不存在|不会|不跟您说|"
SyntaxError: '(' was never closed
```

### 根因

`NEGATION` 用两行字符串拼接，第二行末尾的 `)` 被**放进了字符串内部**，`re.compile(` 的闭合括号丢失：

```python
# 坏（`)` 在引号内 → 字符串没闭合，compile 也没闭合）
                      r"不承诺|不许说|不夸)"
# 好（`)` 属于正则内容，额外补一个 `)` 闭合 compile）
                      r"不承诺|不许说|不夸)")
```

### 影响面（为什么这不是小事）

`eval_run.py` 是唯一的评测入口。它一崩，`--check` / `--rejudge` / 真实评测**三个功能全废**。  
也就是说：**从 10-19 判据定稿之后，任何一次评测都跑不起来。**

### 为什么一直没人发现

`tools/run_all.py` 的第 1 项就是 `py_compile` 全部 `.py`——只要跑一次就会立刻暴露。  
所以真因不是"bug 难发现"，而是**10-19 之后一次体检都没做过**。  
这和 `eval/README.md` 里那句「一个被遗忘的校验器 = 没有校验器」是同一件事的第二次现身：  
上次是**判据**自己误判（4 个 bug），这次是**校验工具**自己编译不过。

### 修法与验证

改动 **1 个字符**（补回 compile 的 `)`），并用三重证据证明「只恢复了语法、没改判据语义」：

| 验证     | 命令                                            | 结果                            |
| ------ | --------------------------------------------- | ----------------------------- |
| ① 题库校验 | `eval_run.py --check`                         | 通过；60 题 / 42:12:6 / 留出集 8     |
| ② 判据回归 | `test_judge.py`                               | **19 例，不一致 0**                |
| ③ 全量重判 | `--rejudge eval/reports/w2_cases60_gold.json` | **60/60 = 100%**，与 10-19 完全一致 |

第 ③ 条是关键：用 10-15 归档的**同一批答案**重打分，结果不变 → 证明修复没有偷偷改变判定行为。  
新报告存档为 `eval/reports/w2_cases60_gold_rejudged_verify.md`，**不覆盖** 10-19 的有效报告。

### 面试怎么讲（比"我修了个 bug"高一层）

> 「判据定稿后我第一次跑体检，发现评测器根本编译不过——语法错误，`--check` 都进不去。  
> 这意味着我之前那份 100% 是谁也复现不了的。修完我用归档答案做了全量重判，数字没变，  
> 才敢继续用。**我的教训是：校验器本身也要进 CI，不能靠人记着跑。**」

## 三、金标可验证性审计：把「38 题人工复核」变成机器证据

### 方法（这是本次的方法论贡献）

拿**判据本身**去判**金标文档原文**（复用 `eval_run.judge()`，含否定语境剔除）：

- 命中 → 该篇正文确实写着 `pattern` 要的具体事实 → **独立支撑**成立
- 不命中 → 该篇只是「话题相关」 → 按《金标规则说明-20261015》第六节第 4 步该删

顺带反向查一遍：`none` / `constraint` 题的 `pattern` 在**全量语料**里命中没有？  
命中就说明「库外」标注是错的。

### 结果

| 项                     | 结果          |
| --------------------- | ----------- |
| `has` 题金标**全部**篇目均可支撑 | **54 / 54** |
| 多答案题里撑不住的冗余篇目         | **0**       |
| 库外题在语料中被命中            | **0**       |
| 未被任何题引用的篇目            | **6**       |

**能证明的**：42:12:6 这个比例不是凑出来的——每篇写进 `gold_sources` 的文档，正文里都真有那个事实。  
**不能证明的**：`pattern` 是否穷尽了合法表述。审计只验「金标够不够」，不验「判据全不全」。  
后者只能靠真实回答 + 人工复核（10-19 那 4 个 bug 就是证据）。
