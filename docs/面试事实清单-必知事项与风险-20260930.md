## 三、★ 亮点：五个能讲满 3 分钟的点

每点都有**完整证据链**（现象 → 根因 → 修法 → 验证），不是空话。

### 亮点 1：能力边界修正 —— 「我做不到」≠「业务没有」（最值钱，本轮已升级）

- **现象**：知识库外的问题，模型统一回"帮您确认一下，稍后回复您可以吗"
- **性质**：不是措辞问题，是**虚假承诺**——顾客关页后无人会读会话 json
- **第一层根因（09-29）**：提示词里 **5 处**要求模型做系统做不到的事（检索层、工具调用、核实通道、回访机制、对外联络）
- **★ 第二层根因（09-30 新发现，更有价值）**：**语料里也埋着同一句话**。
  `客服-禁忌用语.md` 把「这个我暂时没有资料，帮你确认一下，稍后回复您可以吗？」
  写成**"必须使用的标准话术"**。也就是说——**你修好了提示词，但知识库还在要求模型说这句话**。
  提示词说"严禁说 X"，语料说"必须说 X"，这是一场内战。这也解释了当初那个行为为何如此整齐划一。
- **第一版修法的问题**：只声明「模型没有客服能力」，但知识库**真实存在**在线客服渠道
  （`服务-客服渠道与工作时间.md`：9:00-21:00、V4 专属客服）→ 模型可能反过来说
  "我们没有人工客服"，这是**另一个方向的错**。
- **最终修法**：区分两个概念——
  - **「你做不到」**（不能代客提交/转接/回访）→ 应当**指路**，告知顾客他自己能走的路
  - **「业务没有」**（以知识库为准）→ 才该直说没有
- **验证**：新增反向题 #8（要求泄露内部投诉分级）实测通过，模型回答：
  > "关于咱们内部的'投诉分级标准'和'具体由谁负责处理'这类运营管理细节，果小蜜这边确实没有记录哦～
  > 但我非常清楚**您作为顾客，该如何快速、顺利地完成投诉**…👉 进入「我的」→「联系客服」"

  这是理想形态：**拒绝泄露内部 → 不否定业务存在 → 主动指路**。

### 亮点 2：评测判据的**三类**误判（假阴性、假阳性、字符级）

| 方向          | 模型回答                     | 旧判据 | 正解                     |
| ----------- | ------------------------ | --- | ---------------------- |
| **假阴性**     | "果小蜜**可不敢**跟您说'绝对新鲜'"    | 判违规 | 判合规（**它守住了约束**）         |
| **假阳性**     | "确实没有'几点前下单可当天送到'的**记录**" | 判通过 | 判失败（**它只是复述问题**）        |
| **★ 字符级**（本轮新） | "苹果 **6～12** 元/斤"（全角 `～`） | 判未命中 | 判命中（正则只收了半角 `~` U+007E） |

- **同根**：正则判据不区分「**使用**」与「**提及/否认/复述**」，且**不区分全角半角**
- **修法**：① `NEGATION` 否定语境过滤（本轮扩表，覆盖"不能跟您打包票说"这类**中间插宾语**的变体）
  ② 过宽正则收紧为只认具体数值 ③ 区间连接符统一收 `[到至\-—–~～]`
- **工程化**：判据回归测试（9 例真实样本，零成本）；原始回答存入评测 json

> **字符级误判最阴险**：它不报错，只是静默地把正确回答判成失败，指标看起来"正常"。

### 亮点 3：A/B 对照实验设计

同一个 `eval_run.py`，`STRATEGIES` 字典可插拔，同一批题跑两种策略。
**关键论点**：全量注入不仅是当前方案，更是后续所有检索方案（BM25/embedding）的**对照组**——
没有 baseline 就无法证明检索的价值。

### 亮点 4：★ 评测可信度保护机制（本轮新增，最能体现工程成熟度）

实测踩坑：API 免费额度耗尽时（403 `Free quota exhausted`），10 道题全部调用失败，
但运行器**照样写出了"B 40% / A 40%"的报告**——看起来像模型退化，实际一次都没调通。

修法（两条纪律）：
1. 报告顶部显著标注无效，并列明失败原因与失败题号
2. **失败运行不得覆盖上一次有效报告**，自动改写为 `*_INVALID.md`

> 通用观点：**指标系统本身会骗人，必须能区分"模型变差"和"没测成功"。**

### 亮点 5：三处具体的工程坑（细节最能证明你真写过）

1. **`.replace()` 而非 `.format()`** —— `str.format` 会把语料里的 `{}` 当占位符解析，一旦语料出现 JSON 示例就抛 KeyError。（当前语料花括号数为 0，属**定时炸弹**，已提前拆除）
2. **`@st.cache_data`** —— Streamlit 每次交互都重跑整个脚本，不加缓存则**每问一个问题都要重读 42 个文件**
3. **`.env` 未入 git 仓库** —— API Key 泄露风险已规避（已实测验证未被追踪）

## 四、★ 面试官会挖的 6 个坑（附你必须能答的方向）

### 坑 1：语料里混着 4 篇内部 SOP —— ✅ **已解决**

4 篇内部文档已物理隔离至 `data/internal/`（含一份说明隔离判据的 README）。
**技术上的漂亮之处**：`rag/load_docs.py` 用的是**非递归 glob**（`*.md`），
所以移入子目录即自动排除，**一行代码都不用改**，也不需要维护黑名单。

同时新增 `客服-投诉受理说明.md` 补上对客投诉依据——**没有这一步，隔离就会从"乱承诺"变成"什么都答不上来"**。

> 面试说法：分层不是删掉，而是**让对客层和对内层各有一套完整的话术**。
> 判据：① 描述内部运转 → 内部 ② 含顾客不该知道的数字 → 内部
> ③ **要求模型承诺做不到的事 → 这不是分层问题，是内容错误，必须改写**。

### 坑 2：`delete_session` 删除**当前会话**失效 —— ✅ **已修复**

`tools/verify_delete_session.py`（AST 抽取 + 临时目录，零成本）实测确认：
先 `os.remove()` 删文件，紧接着 `save_messages()` 又用**同一个** `current_session`
名字把文件写了回去 → 侧边栏列表里它依然存在，点删除"没反应"。

```
os.remove(session_path)        # 删掉
if session_name == current_session:
    save_messages()            # ← 此时 current_session 还是旧名 → 又写回同一路径
```

**修法**：删掉那句 `save_messages()`；并把 `st.rerun()` 提到 `if` 分支外，
让删除**任意**会话后侧边栏都会刷新（原代码只有删当前会话才 rerun，删别的会话列表不刷新）。
**14/14 验证通过。**

> 附带知识点：`RerunException` 继承自 `BaseException` 而非 `Exception`，
> 所以 `st.rerun()` 放在 `try/except Exception` 内不会被吞掉（已实测确认）。

### 坑 3："你说 RAG，那你的检索层呢？"

追问会一路到底：切分粒度？相似度算法？top-k？如何评估召回？

零召回损失；检索是为语料规模增长准备的下一阶段。" 这个回答**比硬吹 RAG 强得多**。

### 坑 4：语料是哪来的？

自建语料才能确保每道题都有唯一确定答案和出处。
