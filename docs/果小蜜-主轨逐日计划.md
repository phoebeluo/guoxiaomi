### W1 · P0 止血与基线冻结　✅ **已完成（2026-10-14）**

七天做的事：逐条记下 `chunk.py` 的 4 处错 → 逐个修（`OVERLAP` 未定义 / `buf` 类型 / `get_tail` 类型 / L26–27 缩进）→ 抽检 overlap 顺序 → 画评测器数据流 → 跑 `--check` + 判据回归 → **用最新判据离线重判归档 v1 基线**（零 API）→ 清裸字符串。

**完成结论（可写进简历）**

| 指标 | 数值 | 说明 |
|---|---|---|
| 总块数 | **96** | 45 篇 / 29,563 字 |
| 平均块长 | **330.1（实测）** / 342（推算） | 两口径差 3.5%，来自 `strip()` 去掉的 1,241 个空白字符。**对外引用 330.1 并注明口径** |
| 冗余率 | **≈11%** | 重叠 3,366 ÷ 净字数 28,322 = 11.9% |
| `CHUNK_SIZE` | **400** | 中文 1 字 ≈ 1 token |
| 相邻块重叠 | **66.0 字（实测均值）** | 51 个边界，min 50 / max 105；公式预测 65.5 ✅ |
| P95 块长 | **398** | 首次实测，达标（≤450） |

**⚠️ 验收标准已修订**：原「总块数 60–90」与语料规模不自洽（实测 96 > 上限 90），且随扩容必然失效。改为**规模无关**三条：

1. 平均块长 **250–400** 字符　2. **P95 块长 ≤ 450**　3. 每块 `text` 非空、带 `source`

**面试钩子**：我发现原验收标准隐含依赖语料规模、扩语料后必然失效，因此改成规模无关指标——**指标本身也需要被审查**。

### W4 · 检索实验　✅ **已完成（2026-10-28）**

> **设计已变更**：原「三档 × 全量注入」在零成本下不可行（346 篇单题 811K token，三档需 40 倍额度）。
> 改为「检索侧四档 + 检索后注入 A/B」，成本 42M → **0.6M token**，且测的是检索器本身。

| 步 | 结果 |
|---|---|
| 实验设计 | 确认全量注入不可行，改检索侧 + 检索后注入 |
| 同域噪声 | 从 301 篇筛出 **55 篇**提到水果品种的行业文（`data/raw/fruit_noise/`），比"刻意注入矛盾文档"更真实 |
| 四档检索 | 块级 R@5 **恒定 95.8%**，MRR 0.851 → **0.880**；篇级同 |
| 1000 篇档 | ❌ 不可行（1M 窗口 + 额度），346 封顶 |
| 归因 | 规模不是瓶颈。真正瓶颈是**口语↔书面语词汇鸿沟**：48 题 5 题掉出 top-3（#3/#6/#34/#39/#54），token 覆盖率未召回组 **13%** vs 已召回组 **45%** |
| 端到端 A/B | C（理想检索）96% / D（BM25 真实）98% → 逐题复核后 C 的 2 处失败**全是判据误判**（J1/J2）→ **修正后 C 100% / D 98%，检索损失 2 pp，定位到 #6 单题** |

**新增判据缺陷（登记未修）**：J1 `HARD_REFUSAL` 的"查不到"误伤「查不到用户数据」；J2 否定剔除跨不了 9 字以上远距离否定。

## 九、最终产物形态（简历目标）

> 1. **构建知识库接入 A/B 对照组**：无知识库 vs 全量注入，量化「为什么必须检索」（22 题同批，v1 基线归档）。
> 2. **检索质量随语料规模的实测**：45 → 346 篇（7.7 倍），块级 R@5 恒定 95.8%、MRR 0.851→0.880，**证明规模不是瓶颈**；归因到真正瓶颈——口语↔书面语词汇鸿沟（未召回组 token 覆盖率 13% vs 已召回组 45%）。
> 3. **真实检索 vs 理想检索的量化差距**：C 100% / D 98%，**检索损失 2 pp 且定位到单题**（#6，模型诚实拒答，失效在检索端）。
> 4. **为客服智能体设计 3 个可兑现工具 + 自建 MCP Server**，以工具调用替代「无法兑现的虚假承诺」；同步建立工具选择 / 参数 / 越权拒绝三项评测。**主动砍掉需要假数据的工具，因为假数据等于制造新的虚假承诺。**
> 5. 建立能力边界约束层，区分「模型做不到」与「业务没有」。
> 6. **将评测判据本身作为被测对象**：19 例回归、4 类误判修正 + 新登记 J1/J2，确立「失败运行不得覆盖有效报告」的指标纪律。
> 7. 建立**规模无关**的切分验收标准（平均块长 250–400 + P95 ≤ 450），替代会随扩容失效的「总块数 60–90」。
> 8. 服务化：FastAPI + SSE + Dockerfile + **QPS/P99 压测**，并定位到「吞吐瓶颈在上游 RPM 而非应用层」。
